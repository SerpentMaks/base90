# МАСТЕР-ПРОМТ: PWA «Base90» — английский с нуля за 90 дней (iPhone, GitHub Pages)

> **Как пользоваться (для человека):**
> 1. Создай пустую папку, например `~/base90`, положи туда этот файл как `PROMPT.md`.
> 2. Проверь, что стоят Node.js ≥ 20, git и GitHub CLI (`gh auth login` уже выполнен).
> 3. В папке запусти `claude` и напиши: **«Прочитай PROMPT.md целиком и выполняй его по этапам. Начни с этапа 0.»**
> 4. После каждого этапа Claude Code остановится, скажет, что проверить на iPhone, и будет ждать «го дальше».
>
> Всё, что ниже, адресовано Claude Code.

## 0. Твоя роль и главная цель

Ты — senior-разработчик PWA и одновременно методист по обучению английскому языку взрослых русскоговорящих новичков. Твоя задача — спроектировать, наполнить контентом, протестировать и задеплоить на GitHub Pages **офлайн-first PWA**, в котором проходит **всё** обучение английскому на первые 90 дней: слова, грамматика, произношение, аудирование, чтение, повторения, статистика и напоминания.

**Конечная цель ученика** — через 1,5–2 года смотреть фильмы в оригинале без особых трудностей. Эти 90 дней — фундамент: ~1000 самых частых слов и фраз разговорного английского, базовая грамматика, привычка заниматься каждый день и, главное, **понимание на слух**. Поэтому приложение с первого дня делает упор на аудио, а не на чтение.

**Ключевой критерий успеха:** ученик реально занимается 90 дней подряд и не бросает. Методика, которую он не выдержит, хуже простой методики, которую он выдержит. Каждое решение оценивай по двум вопросам: «это эффективно для памяти?» и «это не отобьёт желание зайти завтра?».

## 1. Профиль ученика (учитывай везде)

- Родной язык: русский. Часовой пояс: Europe/Moscow (UTC+3, без перевода часов).
- Уровень: почти ноль. Знает алфавит, правила чтения буквосочетаний, ~100 слов. Считай, что с нуля, но дай быстро «отметить» знакомые слова.
- Сам говорит, что «чуть туп в изучении языков». Значит: маленькие шаги, много повторений, объяснения простым русским языком без терминов (или с переводом термина), мгновенная обратная связь, никакого стыда за ошибки, никаких стен текста.
- Основное устройство: **iPhone** (PWA через Safari → «На экран Домой»). Вторично: ПК, синхронизация желательна, но не критична.
- Учится в вузе примерно 12:00–16:00, посещаемость отмечают. Занятия английским удобны утром до 12 или вечером.
- Время в день: старт **20 минут**, **+10 минут каждые 3 учебных дня**, потолок **90 минут** (настраивается).
- Вариант английского: **американский** (произношение, IPA, голос TTS, написание).
- Язык интерфейса: **русский**.

## 2. Методическая основа (обязательно реализовать, это ядро продукта)

Каждый принцип ниже должен быть виден в коде, а не только в тексте.

### 2.1. Интервальные повторения на FSRS
- Планировщик повторений — **FSRS** через пакет `ts-fsrs` (open-spaced-repetition, MIT, реализует FSRS v6). Не пиши SM-2 сам.
- Желаемая удерживаемость (`request_retention`) по умолчанию **0.90**, в настройках 0.85–0.95.
- Включи `enable_fuzz`, чтобы повторения не слипались в один день.
- Шаги изучения новой карточки внутри сессии: показать → проверить через ~1 мин → через ~10 мин (или в конце сессии). Только после этого карточка уходит в FSRS-расписание.
- Каждый ответ пишется в `reviewLog` (для будущей оптимизации параметров FSRS и статистики).
- Через 30+ дней и ≥1000 логов предложи пользователю «персонализировать алгоритм»: если оптимизатор (`@open-spaced-repetition/binding`) нормально собирается под браузер — используй его, иначе пропусти этот пункт и оставь параметры по умолчанию. Это необязательная фича.

### 2.2. Активное припоминание вместо пассивного просмотра
- Нигде нет режима «просто полистать слова». Сначала ученик пытается вспомнить или ответить, потом видит правильный ответ.
- Оценка для FSRS:
  - **Автопроверяемые упражнения** (ввод, выбор, сборка): оценка выставляется автоматически. Ошибка → `Again`; верно, но медленно (> порога для типа упражнения) или с подсказкой → `Hard`; верно → `Good`; `Easy` автоматически не ставится.
  - **Самооценка** (карточки «вспомнил/не вспомнил»): три большие кнопки «Не вспомнил» / «С трудом» / «Вспомнил» → `Again` / `Hard` / `Good`. Кнопка «Легко» спрятана (долгое нажатие или настройка), чтобы ученик не переоценивал себя.

### 2.3. Сначала аудио
- У каждого английского слова и предложения есть озвучка (TTS, см. §8.4).
- Звук играет автоматически при показе английского (с выключателем).
- Отдельный тип карточек «на слух»: ученик слышит слово или фразу **без текста** и вспоминает значение. Это главный навык для фильмов.
- По умолчанию у каждого слова две карточки: **EN-аудио → значение** (узнавание на слух) и **RU → EN** (воспроизведение). Узнавание вводится первым, воспроизведение — через 1–2 дня после первого успешного узнавания.

### 2.4. Слова по частотности, а не по темам
- Порядок изучения задаёт частотность в **разговорной** речи. Источник — списки NGSL Project (лицензия CC BY-SA 4.0):
  - **NGSL-Spoken 1.2** (721 слово, до 90% покрытия неподготовленной устной речи) — изучается первым;
  - затем **NGSL 1.2** (2809 слов) в порядке ранга, исключая уже пройденные.
- Пул контента готовь с запасом: **~1300 слов + ~200 фраз-чанков**. План на 90 дней — около **950 новых элементов** (слова + чанки, расчёт в §4.4); быстрый ученик может уйти вперёд.
- Чанки — готовые фразы, которые постоянно звучат в фильмах: `I don't know`, `What's going on?`, `Come on`, `I'm gonna…`, `You know what?`, `Let's go`, `I mean`, `Are you kidding?`, `Never mind`, `Hold on` и т. п. Учатся как одно целое.
- Для мотивации показывай в статистике честную справку: по исследованию Webb & Rodgers, для понимания 95% слов в фильмах нужно ~3000 самых частых словарных семей, для 98% — ~6000. Эти 90 дней — первая треть пути.

### 2.5. Слово всегда в контексте и в «i+1»-предложении
- У каждого слова 1–2 примера: короткое предложение с аудио и русским переводом.
- **Правило i+1:** в примере все остальные слова должны быть уже изучены к этому моменту (≥ 90% токенов из ранее изученных + служебные слова). Подбирает билд-скрипт (§7.3).
- Источник примеров — пары предложений Tatoeba eng↔rus (CC BY 2.0 FR; удобная вычищенная выгрузка — manythings.org/anki, файл `rus-eng.zip`). Храни ID предложения и автора для атрибуции. Если подходящего предложения нет, сгенерируй своё простое и пометь `source: "generated"`.

### 2.6. Понятный вход (comprehensible input): истории и диалоги
- **~45 коротких историй** (60–300 слов) и **~70 мини-диалогов** (4–10 реплик) с аудио, сгенерированных под словарь ученика.
- Каждая история привязана к «точке открытия» — индексу в порядке изучения слов. Валидатор (§7.4) гарантирует: на момент открытия ученик знает **≥ 95%** токенов (цель 98%, имена собственные не считаются).
- Чтение по предложениям: аудио → текст скрыт → «показать текст» → тап по слову = перевод + «добавить в колоду».
- После истории 2–4 простых вопроса на понимание (на русском или очень простом английском).
- Сквозные персонажи и сюжет (мини-сериал), чтобы было интересно, что дальше. Темы: учёба, друзья, технологии и программирование, игры, кино, город, еда, работа, путешествия.

### 2.7. Произношение и восприятие звуков для русскоговорящих
Отдельный модуль «Звуки» (первые 3 дня — обязательно, дальше короткими вставками). Целевые проблемы русскоговорящих:
- **/w/ vs /v/** (west/vest, wine/vine, very/worry) — путают в обе стороны;
- **/θ/, /ð/** (think, this) — заменяют на /s/, /z/, /f/, /t/, /d/;
- **долгота и качество гласных:** ship/sheep, full/fool, live/leave, а также /æ/ vs /e/ (bad/bed) и /ʌ/ vs /ɑː/ (cut/cart);
- **дифтонги** (play, go) — не превращать в одну гласную;
- **окончания** `-s` (/s/ /z/ /ɪz/) и `-ed` (/t/ /d/ /ɪd/);
- **слабые формы и шва** (`can` → /kən/, `to` → /tə/, `and` → /ən/, `of` → /əv/) и **связная речь**: `gonna`, `wanna`, `gotta`, `whaddaya`, `lemme`, `kinda`, `'d`, `'ll`, `'ve`, связывание `an apple`. Для понимания фильмов это **критично**.

Упражнения модуля: минимальные пары на слух (выбери, что прозвучало), «расшифруй быструю фразу» (слышишь связную речь → выбираешь полную запись), shadowing (§2.8).

### 2.8. Shadowing и диктант
- **Диктант:** прослушай предложение (скорость 0.85 → 1.0) и напечатай. Сравнение по словам с подсветкой ошибок, регистр и пунктуация игнорируются, опечатка в одну букву считается «почти» и даёт `Hard`.
- **Shadowing:** прослушай фразу → запиши себя (MediaRecorder) → сравни A/B → самооценка. На iOS распознавания речи в установленном PWA нет, поэтому оценка произношения только на слух, по сравнению своей записи с эталоном. Если микрофон недоступен — режим «повтори вслух» без записи.

### 2.9. Грамматика: коротко, на русском, сразу практика
- Микроуроки: экран объяснения (≤ 150 слов по-русски, 3–5 примеров с аудио, без терминологии или с объяснением термина) → 8–12 упражнений сразу.
- Затем правила **спирально** возвращаются: упражнения на пройденную грамматику смешиваются с повторениями (каждое упражнение — отдельная FSRS-карточка типа `grammar`).
- Особый акцент на типичных ошибках русскоговорящих: **артикли** (в русском их нет), обязательное подлежащее (`It is cold`), вспомогательный `do/does/did` в вопросах и отрицаниях, фиксированный порядок слов, `-s` в 3-м лице, `to be` в настоящем времени.

### 2.10. Чередование и разнообразие
- В сессии типы упражнений чередуются (не 30 одинаковых карточек подряд); подряд не больше 5 упражнений одного типа.
- Новое перемешивается со старым.

### 2.11. Адаптивная нагрузка (для «туп в обучении» — особенно важно)
- Прогрессия времени считается по **учебным дням**, а не по календарю (§4.1). Пропустил день — нагрузка не растёт.
- **Защита от завала:** если просроченных повторений больше, чем помещается в ~60% времени дня, новые слова на сегодня = 0, приложение мягко пишет «Сегодня разгребаем повторения — это нормально».
- **Если удерживаемость за 7 дней < 80%**, новые слова урезаются на 30%; объяснить это одной строкой.
- **Мягкий возврат:** если пропущено ≥ 3 дня подряд, план откатывается на одну ступень (−10 минут) и первые 2 дня после возврата — в основном повторения.
- Сессию можно разбить на **подходы по 10–20 минут** в течение дня: прогресс сохраняется после каждого упражнения, «Продолжить» возвращает туда же. 90 минут подряд никто не обязан сидеть.

### 2.12. Мотивация без токсичности
- **Стрик** засчитывается, если за день выполнен «минимум» (по умолчанию: все повторения, которые были к сроку утром, ИЛИ 10 минут активного времени).
- **Заморозки стрика:** +1 за каждые 7 дней подряд, максимум 2 в запасе, тратятся автоматически.
- XP за активное время и правильные ответы (без таблиц лидеров).
- Вехи: 100/250/500/1000 слов, 7/30/60/90 дней, первая история, первый «фильмовый» тест. Короткая анимация + одна фраза.
- Тон всех текстов: дружеский, конкретный, без давления и без чувства вины. Ошибка — это нормальная часть процесса («Ошибка = сигнал памяти, что слово надо укрепить»).

## 3. Учебная программа на 90 дней (13 недель)

Номер недели считается от **учебного дня**: неделя N = учебные дни 7(N−1)+1 … 7N. Грамматика и фонетика недели открываются по учебным дням; слова идут непрерывным потоком по частотности.

| Неделя | Грамматика (микроуроки) | Звуки / аудирование | Фокус |
|---|---|---|---|
| 1 | `to be` (am/is/are), личные местоимения, `this/that`, `a/an` — введение | Звуки EN vs RU: /w/–/v/, /θ/–/ð/, долгие и краткие гласные; числа 1–20 на слух | Привыкнуть к ритуалу, первые 50–70 слов |
| 2 | Вопросы и отрицания с `to be`, `there is/are`, притяжательные `my/your/his…`, `'s` | /æ/–/e/, /ʌ/–/ɑː/; числа до 100, время на слух | Диалоги-знакомства |
| 3 | Present Simple: утверждения, 3-е лицо `-s` | Окончания `-s` (/s/ /z/ /ɪz/) | Рутина, дни недели |
| 4 | Present Simple: `do/does` в вопросах и отрицаниях, наречия частоты; `the` vs `a` | Ударение в словах, шва /ə/ | **Тест месяца 1** (день 28) |
| 5 | Present Continuous; Simple vs Continuous | Слабые формы `am/is/are`, сокращения `I'm/you're` | Первые истории |
| 6 | `can/can't`, повелительное наклонение, `let's` | `can` /kən/ vs `can't` /kænt/ на слух | Просьбы и предложения |
| 7 | Past Simple: `was/were`, правильные глаголы | Окончания `-ed` (/t/ /d/ /ɪd/) | Рассказ о вчерашнем дне |
| 8 | Past Simple: топ-30 неправильных глаголов, `did` в вопросах и отрицаниях | Связывание слов (linking) | **Тест месяца 2** (день 56) |
| 9 | Будущее: `going to` / `gonna`, `will` / `'ll` | `gonna`, `'ll`, `wanna`, `gotta` | Планы |
| 10 | Объектные местоимения, предлоги `in/on/at` (время и место), `some/any`, `much/many` | Быстрая речь: «расшифруй фразу» | Диалоги из жизни |
| 11 | Present Perfect (база: `ever/never/just/already`, `I've been`) | `'ve`, `'s` = has/is на слух | Частая форма в фильмах |
| 12 | Модальные `should/have to/might/could`, `would/'d` (`I'd like`), сравнения | Реплики из фильмов: `you know`, `I mean`, `kind of` → `kinda` | **Мост к фильмам** (§6.12) |
| 13 | Топ-30 фразовых глаголов (`get up`, `find out`, `come on`, `go on`, `figure out`, `pick up`…), повторение всего | Длинные диалоги на нормальной скорости | **Итоговый тест** (день 90) и план на следующие 3 месяца |

Тесты месяца — 10–15 минут: слова на слух, грамматика, диктант, понимание диалога. Результат сохраняется, показывается прогресс между тестами. Тесты не влияют на FSRS.

После 90-го дня приложение **не заканчивается**: продолжаются повторения и новые слова из пула, грамматика уходит в режим повторения, открываются оставшиеся истории. На экране — честная рекомендация, что делать дальше (больше сериалов с английскими субтитрами).

## 4. Ежедневный план и тайминг

### 4.1. Бюджет времени
```
k = количество уже засчитанных учебных дней (день засчитан, если выполнено ≥ 80% плана)
minutesToday = min(cap, start + step * floor(k / period))
по умолчанию: start = 20, step = 10, period = 3, cap = 90
```
- Потолок 90 достигается на 22-й учебный день. За 90 учебных дней набирается **~121 час** (1050 мин за первые 21 день + 69 × 90 мин).
- Все четыре параметра — в настройках.
- Учитывается только **активное время**: вкладка видима, и последнее действие было не больше 60 секунд назад. Таймер на экране не давит: показывается кольцо прогресса, без обратного отсчёта.
- После выполнения плана: «План выполнен 🎉. Можно продолжить (повторения/истории) или отдохнуть». Сверх плана — только по желанию.

### 4.2. Состав дня (доли от бюджета)

| Блок | Месяц 1 | Месяц 2 | Месяц 3 |
|---|---|---|---|
| Повторения FSRS (всегда первыми) | 35% | 35% | 35% |
| Новые слова и чанки | 25% | 20% | 15% |
| Грамматика (урок + упражнения) | 15% | 15% | 10% |
| Звуки / минимальные пары / связная речь | 15% | 10% | 10% |
| Аудирование: диктант, диалоги, shadowing | 10% | 15% | 15% |
| Истории (понятный вход) | — (с недели 5) | 5% | 15% |

Неиспользованная доля (например, повторений сегодня мало) перетекает в аудирование и истории, **а не** в новые слова.

### 4.3. Порядок внутри сессии
1. Разминка: 3–5 лёгких повторений (успех в начале).
2. Повторения FSRS вперемешку с шагами изучения вчерашних новых карточек.
3. Новые слова порциями по 3–5: знакомство → сразу 2 проверки → дальше по шагам.
4. Микроурок грамматики (если открыт новый) или упражнения на пройденную.
5. Звуки / аудирование.
6. История или диалог.
7. Итог: что сделано, сколько минут, стрик, одна фраза поддержки.

### 4.4. Новые слова в день
```
newToday = clamp(5, 25, round(minutesToday * shareNew / 1.5))   // ~1,5 мин на новое слово со всеми шагами
```
плюс защита от завала (§2.11). При таких параметрах за 90 учебных дней выходит ≈ 950 слов и чанков (без пропусков и без урезаний). Не делай выше 25 в день, даже если ученик просит: предупреди, что через 2–3 недели это обернётся завалом повторений.

## 5. Онбординг

## 7. Контент и билд-пайплайн

Контент генерируется **на этапе сборки** скриптами в `/scripts` → JSON в `/src/content/` → прекэшируется Service Worker'ом. В рантайме никаких внешних API для контента.

### 7.1. Источники
1. **NGSL 1.2 и NGSL-Spoken 1.2** — скачать с newgeneralservicelist.com (CSV/XLSX). Лицензия CC BY-SA 4.0 → в репозитории `CONTENT_LICENSES.md` + экран «Источники» в приложении; производный список слов публикуется под той же лицензией. Если скачивание недоступно — остановись и попроси пользователя скачать файл вручную, **не выдумывай** частотный список.
2. **Tatoeba eng↔rus** — `https://www.manythings.org/anki/rus-eng.zip` (или экспорт с tatoeba.org/downloads). CC BY 2.0 FR → сохранять `tatoebaId` и автора для каждого предложения, атрибуция на экране «Источники».
3. **Всё остальное** (переводы, IPA, заметки, грамматика, истории, диалоги, чанки, минимальные пары) генерируешь ты сам и проверяешь (§7.5).

### 7.2. Схемы данных (zod + TypeScript)
```ts
type WordItem = {
  id: string;              // "w_0001"
  lemma: string;           // "get"
  rank: number;            // порядок изучения (NGSL-S, затем NGSL)
  pos: string[];           // ["verb"]
  ipa: string;             // US: "/ɡɛt/"
  ru: string[];            // ["получать", "становиться", "добираться"] — главное значение первым
  forms?: string[];        // ["got", "gotten", "getting", "gets"]
  note?: string;           // ловушка на русском, ≤ 120 символов
  examples: { en: string; ru: string; source: "tatoeba" | "generated"; tatoebaId?: number; author?: string }[];
  tags?: string[];         // ["chunk", "phrasal", "film"]
};
type GrammarLesson = { id: string; week: number; order: number; title: string; explanationMd: string; examples: {en: string; ru: string}[]; drills: Drill[] };
type Story = { id: string; unlockRank: number; title: string; sentences: { en: string; ru: string }[]; questions: Question[]; coverageAtUnlock: number };
type Dialogue = { id: string; unlockRank: number; lines: { speaker: string; en: string; ru: string }[] };
type MinimalPair = { id: string; a: string; b: string; ipaA: string; ipaB: string; contrast: "w-v" | "th-s" | "i-iː" | ... };
type ConnectedSpeech = { id: string; spoken: string; full: string; ru: string };  // "whaddaya" → "what do you"
```

### 7.3. Скрипты
- `scripts/build-words.ts` — объединить NGSL-S + NGSL, задать `rank`, обогатить переводами/IPA/заметками (генерация пачками по 50 слов с последующей проверкой), подобрать примеры по правилу i+1 (§2.5): из пар Tatoeba брать предложения 3–10 слов, где все токены, кроме целевого, имеют `rank` меньше целевого или входят в служебные слова; приоритет короткому и разговорному.
- `scripts/build-stories.ts` — генерация историй/диалогов под `unlockRank` + запуск валидатора.
- `scripts/validate-content.ts` — запускается в CI перед сборкой. Сборка **падает**, если:
  - JSON не проходит zod-схему;
  - есть дубли `id` или `lemma` (без явного тега омонима);
  - ссылки на несуществующие слова;
  - история или диалог ниже 95% покрытия на момент `unlockRank`;
  - у предложения Tatoeba нет атрибуции.

### 7.4. Валидатор покрытия
Токенизация + та же лемматизация, что в §6.12 (общий модуль `src/lib/lemmatize.ts`, покрытый тестами). Имена собственные (из списка персонажей) и числа не считаются. Отчёт `content-report.md` со списком историй, их покрытием и незнакомыми словами.

### 7.5. Контроль качества контента (делаешь сам)
- Переводы: самое частое разговорное значение первым; не больше 3 значений; для многозначных (`get`, `make`, `take`) — значения с примерами в `note`.
- Отдельно проверь **ложных друзей** (actual, magazine, sympathetic, accurate, fabric, list, family name…).
- IPA — американская норма.
- Тексты для TTS не должны содержать того, что синтезатор прочитает неверно (сокращения вида `St.`, символы).
- Вычитай каждое сгенерированное предложение: грамматика, естественность («так скажет носитель?»).
- В `content-report.md` выпиши всё, в чём не уверен, — пользователь посмотрит.

## 8. Технологии и архитектура

### 8.1. Стек
- **Vite + React + TypeScript** (strict), **Tailwind CSS**.
- **vite-plugin-pwa** в режиме `injectManifest` (свой Service Worker с обработчиками `push` и `notificationclick`), Workbox для прекэша.
- **Dexie** (IndexedDB) для прогресса.
- **ts-fsrs** для расписания.
- **zod** для схем контента и синхронизации.
- **Vitest** для юнит-тестов, опционально Playwright для e2e.
- Без бэкенда. Без аналитики и трекеров.

### 8.2. Структура
```
/src
  /content        # сгенерированный JSON (в git)
  /lib            # fsrs.ts, planner.ts (бюджет и состав дня), session.ts, lemmatize.ts, tts.ts, sync.ts, push.ts, time.ts
  /db             # dexie schema + миграции
  /features       # today, session, exercises/*, stories, grammar, sounds, film-bridge, stats, settings, onboarding
  /ui             # компоненты
  sw.ts           # service worker
/scripts          # билд контента, валидация, отправка пушей
/.github/workflows  deploy.yml, remind.yml, keepalive.yml
```

### 8.3. Данные (Dexie)
- `cards` — `{ id, itemId, kind: 'listen'|'produce'|'cloze'|'grammar'|'pair'|..., fsrs: Card, learningStep?, createdAt, updatedAt, suspended? }`
- `reviewLogs` — `{ id (uuid), cardId, rating, reviewedAt, elapsedMs, exerciseType }` — только добавление, никогда не меняются.
- `days` — `{ date (YYYY-MM-DD по Москве), plannedMin, activeMin, counted, newIntroduced, reviewsDone }`
- `progress` — открытые уроки, истории, тесты, вехи, заморозки, XP.
- `settings` — все настройки.
- Даты «дня» считаются по Europe/Moscow с границей суток в **04:00** (занятие в 01:00 засчитывается во вчерашний день).
- Миграции схемы версионируются; данные пользователя не теряются при обновлениях.

### 8.4. Озвучка (TTS)
- `speechSynthesis` (Web Speech API). На iOS синтез разрешён только после жеста пользователя → первый звук сессии запускается по тапу «Начать».
- Выбор голоса: фильтр `lang.startsWith('en-US')`, приоритет «улучшенным» системным голосам; в настройках — список с прослушиванием. Подсказка: на iPhone можно скачать более качественный голос в «Настройки → Универсальный доступ → Устная речь → Голоса → English».
- Скорость: 0.85 для новых предложений, 1.0 — по умолчанию, 0.75 — по долгому нажатию.
- Обработать: голоса грузятся асинхронно (`voiceschanged`), `cancel()` перед новым воспроизведением, нет голосов → понятное сообщение.
- Абстракция `tts.speak(text, opts)`, чтобы позже можно было заменить на заранее сгенерированные аудиофайлы.

### 8.5. Ограничения iOS (учесть обязательно)
- Web Push работает **только** у PWA, добавленного на экран «Домой» через Safari (iOS 16.4+). Запрос разрешения — только по жесту пользователя.
- **Распознавания речи (SpeechRecognition) в установленном PWA на iOS нет** → не используй его как основную функцию; можно включать только при успешной фиче-детекции в браузере.
- `getUserMedia`/MediaRecorder в standalone-режиме работают, но капризно: поток может замолкнуть при смене маршрута или после повторного открытия. Поэтому: запись без смены URL/route (состояние внутри экрана), после записи всегда `track.stop()` на всех треках, при `visibilitychange` заново запрашивать поток, при ошибке — тихий откат на «повтори вслух без записи».
- Background Sync, Periodic Background Sync и Notification Triggers на iOS недоступны → все напоминания идут только через серверный пуш (§9).
- Хранилище: вызвать `navigator.storage.persist()`; бэкап через Gist (§10) и экспорт в файл — обязательны, потому что iOS может очистить данные сайта.
- Учесть `safe-area-inset-*`, `apple-touch-icon` 180×180 PNG, `theme-color`, `display: standalone`, корректные `start_url`/`scope` с base-путём репозитория.
- Badging API: `navigator.setAppBadge(dueCount)` на иконке (iOS 16.4+ для установленных приложений) — показывать число карточек к повторению.

### 8.6. GitHub Pages
- Для бесплатного Pages репозиторий должен быть **публичным** → в коде и истории git **никогда** не должно быть токенов, ключей, email, подписок на пуши.
- `vite.config` → `base: '/<repo-name>/'`. Навигация — `HashRouter` или внутреннее состояние (без 404 на глубоких ссылках).
- `deploy.yml`: push в `main` → `npm ci` → `validate-content` → тесты → build → `actions/upload-pages-artifact` → `actions/deploy-pages`.
- Обновление приложения: при новом SW показывать плашку «Доступно обновление → Обновить» (не перезагружать посреди упражнения).

## 9. Напоминания: Web Push через GitHub Actions

Сервера нет, поэтому «будильник» — запланированный workflow GitHub Actions, который отправляет Web Push по протоколу VAPID.

### 9.1. Настройка (один раз)
1. Ты генерируешь VAPID-ключи: `npx web-push generate-vapid-keys --json`.
2. Публичный ключ → `VITE_VAPID_PUBLIC_KEY` (не секрет, можно в конфиг сборки).
3. Приватный ключ → секрет репозитория `VAPID_PRIVATE_KEY`; `VAPID_SUBJECT` = `mailto:<email пользователя>` → тоже секрет (email не должен быть в публичном репо). Поставь секреты через `gh secret set`, **спросив у пользователя email**.
4. Связь приложения с workflow — через секретный Gist (§10): приложение пишет туда `push-subscription.json` и `status.json`, workflow их читает. Секреты: `GIST_ID` и `GIST_TOKEN` (токен только со scope `gist`).
5. **Запасной вариант без Gist:** в настройках приложения кнопка «Скопировать подписку» → пользователь сохраняет JSON как секрет `PUSH_SUBSCRIPTION`. Тогда напоминания «глупые» — по фиксированному времени, без учёта того, позанимался ли он уже.

### 9.2. status.json (пишет приложение)
```json
{
  "updatedAt": "2026-11-17T19:05:00+03:00",
  "studyDate": "2026-11-17",
  "plannedMin": 40, "activeMin": 12, "minimumDone": false,
  "dueCount": 23, "streak": 6, "freezes": 1,
  "reminderTimes": ["10:00", "19:00"], "lastCallTime": "22:00",
  "quiet": false, "paused": false
}
```
Обновляется: при открытии приложения, после каждого подхода, при `visibilitychange → hidden`, при изменении настроек.

### 9.3. remind.yml
- `on: schedule` — **каждый час в нескруглённую минуту** (например `cron: '23 5-19 * * *'` в UTC = 08:23–22:23 по Москве) + `workflow_dispatch` с входом `force` (boolean: отправить сейчас, игнорируя слоты и статус) для теста. Если GitHub поддерживает поле `timezone:` в расписании — можешь указать `Europe/Moscow`, иначе считай в UTC (МСК = UTC+3).
- Скрипт `scripts/send-reminder.ts` (библиотека `web-push`):
  1. Читает `status.json` и подписку из Gist.
  2. Считает текущее московское время. Находит слот: ближайшее прошедшее `reminderTime` или `lastCallTime`, по которому ещё не отправляли сегодня (журнал отправок — `sent-log.json` в том же Gist).
  3. Не отправляет, если: `minimumDone` (для обычных слотов) или план выполнен полностью; `paused`; ночь (23:00–08:00); уже отправлено ≥ 3 за сутки.
  4. Текст конкретный и короткий, варианты чередуются:
     - «23 слова ждут повторения — ~8 минут» / «Сегодня 40 минут, начнём с 10?»
     - последний слот: «Стрик 6 дней 🔥 — хватит 10 минут, чтобы его сохранить»
     - если есть заморозка: «Можно и отдохнуть — заморозка спасёт стрик. Но 5 минут повторений будут кстати»
  5. Ответ 404/410 от push-сервиса → помечает подписку как истёкшую в Gist; приложение при следующем открытии подписывается заново и перезаписывает её (на iOS подписки иногда пропадают — проверяй `pushManager.getSubscription()` при каждом запуске).
- Payload: `{ title, body, url: '/<repo>/#/today', badge: dueCount }`.

### 9.4. Service Worker
- `push` → **всегда** `showNotification` (iOS требует видимое уведомление на каждый пуш), `setAppBadge`.
- `notificationclick` → фокус на открытом окне или `clients.openWindow(url)`.

### 9.5. Ограничения, которые нужно учесть и объяснить пользователю
- Расписание GitHub Actions работает по принципу best effort: запуски могут задерживаться (особенно в начале часа) и изредка пропадать. Напоминание может прийти на 15–60 минут позже — для учёбы это нормально.
- Запланированные workflow в публичном репозитории **автоматически отключаются после 60 дней без активности**, а курс длится 90. Сделай `keepalive.yml`: раз в неделю вызывать API `PUT /repos/{owner}/{repo}/actions/workflows/remind.yml/enable` (через `GITHUB_TOKEN` с правом `actions: write`) или, если этого недостаточно, раз в 3 недели делать пустой служебный коммит. Проверь, что выбранный способ реально работает.
- Минуты Actions для публичных репозиториев бесплатны.

### 9.6. Внутри приложения
- Если сегодня план не начат — плашка на экране «Сегодня».
- Бейдж на иконке = число карточек к повторению.
- Кнопка «Пауза напоминаний на N дней».
- Кнопка «Проверить уведомления»: показывает локальное `showNotification` (проверка разрешения) и даёт инструкцию, как запустить `remind.yml` вручную (GitHub → Actions → Run workflow) с флагом `force: true`, чтобы проверить настоящий пуш.

## 10. Синхронизация и бэкап (GitHub Gist, без своего сервера)

- В настройках: «Подключить синхронизацию» → пошаговая инструкция по созданию **classic** Personal Access Token **только со scope `gist`** (или fine-grained с правом Gists: read & write, если доступно) → вставить токен → приложение создаёт **секретный** Gist или подключается к существующему по ID.
- Токен хранится только локально на устройстве (IndexedDB), никогда не попадает в git. Предупреди: токен даёт доступ к гистам пользователя — нужен отдельный токен только под это приложение.
- Файлы в Gist: `progress.json` (снимок), `status.json`, `push-subscription.json`, `sent-log.json`.
- Слияние: `cards` / `days` / `progress` — по записи, побеждает больший `updatedAt`; `reviewLogs` — объединение по `id`. Сжимать снимок (gzip + base64), если он больше ~500 КБ.
- Когда синхронизировать: при открытии, после подхода, при уходе в фон, по кнопке. Офлайн → очередь, синхронизация при появлении сети.
- На ПК тот же URL в браузере → «Подключить синхронизацию» → тот же токен и Gist ID → прогресс общий.
- Плюс всегда доступно: «Экспорт прогресса в файл» / «Импорт из файла».

## 11. Экраны и UX

- **Сегодня:** кольцо «X / Y минут», большая кнопка «Начать / Продолжить», стрик 🔥 и заморозки, «к повторению: N», что нового сегодня (урок недели, история), напоминание о тесте.
- **Сессия:** тонкий прогресс-бар сверху, крестик «Пауза» (прогресс сохраняется), без отвлекающей навигации.
- **Словарь:** поиск, фильтры (новые / изучаемые / выученные / проблемные), карточка слова с аудио, кнопки «приостановить» и «я это знаю».
- **Прогресс:** слов выучено (stability ≥ 21 день) и в изучении, часов всего, тепловая карта дней, удерживаемость за 7/30 дней, прогноз повторений на 7 дней, результаты тестов, вехи, путь к 3000 словам (§2.4), учебный день N из 90.
- **Уроки:** список грамматики по неделям (пройденные можно перечитать), модуль «Звуки», истории.
- **Настройки:** параметры времени (start/step/period/cap), напоминания, удерживаемость, голос и скорость, IPA вкл/выкл, ввод клавиатурой или плитками, синхронизация, экспорт/импорт, «Источники и лицензии», сброс.
- Дизайн: чистый, спокойный, крупная типографика, тёмная тема автоматически (`prefers-color-scheme`), один акцентный цвет. Анимации короткие (≤ 200 мс), уважать `prefers-reduced-motion`.
- Доступность: контраст AA, подписи у кнопок, работа одним пальцем.
- Каждые 7 учебных дней — «Итоги недели»: минуты, слова, лучшая серия, одна конкретная рекомендация.

## 14. Правила работы для тебя (Claude Code)

1. Работай этапами, не пытайся сделать всё за один заход. Каждый этап должен оставлять рабочее задеплоенное приложение.
2. Сначала мелкий вертикальный срез (одно упражнение от начала до конца), потом расширение.
3. **Спрашивай** только о том, что нельзя решить самому: логин и имя репо, email, создание публичного репо, установка секретов, сомнительный контент. Всё остальное решай сам и записывай решения в `DECISIONS.md`.
4. **Никогда** не коммить токены, ключи, email, подписки на пуши и пользовательские .srt. Добавь проверку (например, `gitleaks` в CI или простой grep-скрипт pre-commit).
5. Тесты обязательны для: `planner`, `fsrs`-обёртки, `lemmatize`, `sync`-слияния, проверки ответов (сравнение строк, опечатки), `send-reminder` (логика слотов и тихих часов).
6. Не тащи тяжёлые зависимости. Никакой аналитики, трекеров и внешних шрифтов с CDN (шрифты — системные или локальные).
7. Контент — главная ценность: лучше 900 идеально проверенных слов, чем 1300 с ошибками в переводах.
8. Если что-то из этого промта технически невозможно или противоречит реальности (API не работает на iOS и т. п.), не делай вид, что работает: сообщи, предложи альтернативу, запиши в `DECISIONS.md`.
9. Все тексты интерфейса — по-русски, простым языком, на «ты».
10. В конце каждого этапа обнови `CHANGELOG.md`.
